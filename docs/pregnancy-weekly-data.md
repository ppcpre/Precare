**สาเหตุ:** น่าจะเป็นปัญหาของตารางที่สร้างจาก *น้ำหนักแรกเกิด* แทนการวัดในครรภ์ —

**ทำไมเลือก WHO:**
1. วัดในครรภ์จริงจากครรภ์ปกติที่ติดตามต่อเนื่อง ไม่ใช่จากน้ำหนักแรกเกิด
2. **มีไทยอยู่ในการศึกษา** (ม.ขอนแก่น N=121 จาก 10 ประเทศ รวม 1,387 ราย)
3. ใกล้เคียงสูตร Hadlock ที่เครื่องอัลตราซาวด์ใช้คำนวณ EFW — แอปกับหมอพูดตรงกัน

**เพิ่มช่วงปกติด้วย** ไม่ใช่แค่เปลี่ยนตัวเลข — การ์ดแสดง "ค่ากลาง + ช่วงปกติ
(เปอร์เซ็นไทล์ 10–90)" เพราะครึ่งหนึ่งของเด็กปกติต้องต่ำกว่าค่ากลางอยู่แล้ว
การโชว์เลขเดียวทำให้พ่อแม่ครึ่งหนึ่งคิดว่าลูกตัวเล็กผิดปกติ

### ⚠️ รอยต่อที่สัปดาห์ 13→14 (23 → 90 ก.)

WHO เริ่มที่สัปดาห์ 14 เพราะก่อนหน้านั้นทางคลินิก**ไม่ได้คิดน้ำหนัก** เขาวัด
ความยาวหัวถึงก้น (CRL) แทน ตัวเลขสัปดาห์ 8–13 จึงยังเป็นของชุดเดิมซึ่งน่าจะต่ำ
เหมือนกัน แต่ยังไม่มีแหล่งอ้างอิงที่ดีกว่ามาแทน

ในแอปจึงกำกับไว้ว่า *"ช่วงนี้ยังไม่มีเกณฑ์มาตรฐาน น้ำหนักเป็นค่าประมาณ"*
และไม่แสดงช่วงปกติให้

**ถ้าเจอแหล่งที่เชื่อถือได้สำหรับสัปดาห์ 8–13 ให้แก้พร้อมกันทั้ง `docs/` และ
`src/data/weekly-content.ts` — อย่าแก้ตัวเลขให้เส้นเรียบโดยไม่มีที่มา**

### ⚠️ ค้างไว้: รอยต่อของ "ความยาว" ที่สัปดาห์ 25 (30.0 → 34.6 ซม.)

เจอตอนไล่ตรวจชุดเดียวกันหลังแก้น้ำหนัก — ความยาวกระโดด 4.6 ซม. ในสัปดาห์เดียว
ทั้งที่สัปดาห์อื่นเพิ่มราว 1.1 ซม.

| สัปดาห์ | 22 | 23 | 24 | **25** | 26 |
|---|---|---|---|---|---|
| ความยาว | 27.8 | 28.9 | 30.0 | **34.6** | 35.6 |
| เพิ่มจากสัปดาห์ก่อน | +1.1 | +1.1 | +1.1 | **+4.6** | +1.0 |

**วินิจฉัย:** เป็นข้อมูลสองชุดต่อกัน สัปดาห์ 21–24 ก้าวทีละ 1.1 ซม. เป๊ะทุกสัปดาห์
(ดูเหมือนเติมเอาเอง) ส่วน 25–40 เป็นอีกชุดที่อยู่สูงกว่าแนวของ 21–24 ราว 3.5 ซม.
ตารางที่อิง WHO ให้สัปดาห์ 24 = 32.2 ซม. ซึ่งอยู่ระหว่างสองชุด — บล็อก 21–24
ของเราจึงน่าจะสั้นไป

**ทำไมยังไม่แก้:** ความยาวทั้งตัวของทารก **วัดด้วยอัลตราซาวด์ไม่ได้** หมอวัด
BPD / HC / AC / FL แล้วคำนวณน้ำหนัก ส่วนความยาวทั้งตัววัดได้ตอนคลอดเท่านั้น
ตารางความยาวรายสัปดาห์ทุกเจ้าจึงเป็นค่าทางอ้อม และที่หาเจอไม่มีเจ้าไหนระบุ
วิธีวัดชัดเจนตลอดช่วง 21–32
- WHO ไม่ตีพิมพ์ความยาวทารก (มีแต่ BPD/HC/AC/FL)
- INTERGROWTH-21st มีความยาวแรกเกิด แต่ตารางเริ่มที่ 33 สัปดาห์
- ตาราง Utah ต้นทางระบุว่าวัดแบบ crown-rump ทั้งตาราง ซึ่งเป็นไปไม่ได้
  (crown-rump ที่ 25 สัปดาห์ราว 22 ซม. ไม่ใช่ 34.6)

**ที่ทำไปแล้ว:** บอกผู้ใช้ตรงๆ บนการ์ด (กด "ทำไมตัวเลขเพิ่มขึ้นเยอะจากสัปดาห์ก่อน")
และเพิ่มเทสต์ `ความยาวกระโดดได้เฉพาะสัปดาห์ที่บันทึกเหตุผลไว้แล้ว` ซึ่งจะแดง
ทันทีถ้ามีรอยใหม่โผล่ หรือมีคนแก้ตัวเลขให้เส้นเรียบโดยไม่อัปเดต
`LENGTH_JUMP_WEEKS`

**ถ้าจะแก้ให้จบ** ต้องได้ตารางความยาวที่ระบุวิธีวัดชัดเจนครอบคลุม 21–40 หรือ
เปลี่ยนไปแสดง **ความยาวกระดูกต้นขา (FL)** แทน ซึ่ง WHO มีข้อมูลอยู่ (ตารางที่ 9
หน่วยมิลลิเมตร) และเป็นค่าที่เครื่องอัลตราซาวด์วัดจริง ไม่มีรอยต่อ

**ตัดสินใจแล้วว่าไม่เปลี่ยนเป็น FL (30 ต.ค. 2569)** — การ์ดใบนี้มีไว้ให้เห็นภาพว่า
ลูกตัวประมาณไหน ไม่ได้มีไว้รายงานผลตรวจ "ยาว 34.6 ซม. ตัวประมาณฟักทองลูกเล็ก"
สื่อกับคนอ่านได้ ส่วน "กระดูกต้นขายาว 4.8 ซม." ถูกต้องกว่าแต่ไม่มีใครนึกออกว่า
แปลว่าตัวใหญ่แค่ไหน เท่ากับเอาสิ่งที่การ์ดมีไว้ทำไปแลกความแม่นยำของตัวเลขประดับ
ที่มีคำอธิบายกำกับอยู่แล้ว

ที่ FL จะมีที่ยืนคือฟีเจอร์คนละตัว — **บันทึกผลอัลตราซาวด์** (กรอก BPD / HC / AC /
FL จากใบผลที่หมอให้ แล้วบอกว่าอยู่เปอร์เซ็นไทล์ไหนและวาดกราฟข้ามครั้ง) ตรงนั้น
ผู้ใช้มีตัวเลขอยู่ในมือแล้วและอยากรู้ว่ามันแปลว่าอะไร

## ⚠️ ก่อนนำไปใช้ ต้องอ่าน

1. **ตัวเลขทั้งหมดเป็นค่าเฉลี่ย** ทารกแต่ละคนต่างกันได้มาก — ในแอปต้องมีข้อความกำกับว่า *"เป็นค่าเฉลี่ยเพื่อการอ้างอิงเท่านั้น ขนาดของลูกน้อยแต่ละคนต่างกันได้ กรุณาปรึกษาแพทย์"*
2. **ไม่ใช่คำแนะนำทางการแพทย์** — เป็นข้อมูลให้ความรู้ทั่วไป ห้ามใช้แทนการวินิจฉัยหรือคำแนะนำจากแพทย์
3. **ควรให้ผู้มีความรู้ทางการแพทย์ตรวจทานก่อนขึ้นระบบจริง** โดยเฉพาะคำบรรยายพัฒนาการภาษาไทย ที่ผมเรียบเรียงจากต้นฉบับภาษาอังกฤษ
4. **สัปดาห์ 4–7 ไม่มีตัวเลขความยาว/น้ำหนัก** เพราะเล็กเกินกว่าจะวัดเป็นมาตรฐานได้ ให้แสดงเฉพาะการเทียบขนาดกับผลไม้

**การวัดความยาว:** สัปดาห์ 8–20 วัดแบบ **crown-rump** (หัวถึงก้น) · ตั้งแต่สัปดาห์ 21 เปลี่ยนเป็น **crown-heel** (หัวถึงส้นเท้า) — จึงเห็นตัวเลขกระโดดจาก 16.4 ซม. เป็น 26.7 ซม. **ต้องอธิบายจุดนี้ในแอป** ไม่งั้นผู้ใช้จะตกใจว่าทำไมลูกโตขึ้น 10 ซม. ในสัปดาห์เดียว

## หมายเหตุเรื่องการเทียบขนาด

ต้นฉบับภาษาอังกฤษเทียบกับผลไม้ฝรั่ง (poppy seed, rutabaga, jicama) ที่คนไทยไม่คุ้น **ผมแปลงเป็นผลไม้/ผักที่คนไทยเห็นภาพออก** เช่น มะเขือพวง ส้มจี๊ด มะละกอ มะม่วง มะพร้าว ส้มโอ ฟักทอง — ขนาดใกล้เคียงของเดิม แต่สื่อสารได้จริงกับผู้ใช้ไทย

### วิธีใส่ภาพประกอบ 37 ภาพ

UI พร้อมแล้วและ **ทำงานได้โดยยังไม่มีไฟล์** — ถ้าโหลดรูปไม่ขึ้นจะแสดงไอคอนทารกแทน
ไม่ใช่ไอคอนรูปพังของเบราว์เซอร์ ใส่ทีละภาพได้ ไม่ต้องครบ 37 ก่อนถึงจะใช้ได้

ตาม design-system.md ข้อ 5 ให้ใช้ illustration แบบ flat/organic เส้นนุ่ม
โทนสีเดียวกับพาเลตต์ ไม่ใช้ภาพถ่ายจริง · ขนาด 96×96 ให้น้ำหนักเส้นสม่ำเสมอกันทั้งชุด

ชื่อไฟล์ผูกกับเลขสัปดาห์แบบเติมศูนย์ (`w04`–`w40`) เพื่อให้เรียงถูกใน bucket:

```bash
npx wrangler r2 object put precare-assets/weekly/size/w24.webp --file=./w24.webp --remote
```

ใส่ครบทั้งชุดทีเดียว:

```bash
for w in $(seq -w 4 40); do
  [ -f "./art/w$w.webp" ] && npx wrangler r2 object put "precare-assets/weekly/size/w$w.webp" --file="./art/w$w.webp" --remote
done
```

เสิร์ฟผ่าน `/api/asset/weekly/size/w24.webp` (bucket public, cache 1 ปี, ไม่ต้องล็อกอิน)
**ห้ามเอาอะไรที่เป็นของผู้ใช้ลง `precare-assets`** — ของผู้ใช้อยู่ `precare-photos` ซึ่งเช็คสิทธิ์ทุก request

## โครงสร้างข้อมูลที่แนะนำ

เก็บเป็น **static JSON ในโค้ด ไม่ต้องเข้า D1** เพราะเป็นข้อมูลคงที่ 37 แถว ไม่มีใครแก้ — ประหยัดทั้ง row reads และ latency

```ts
// src/data/weekly-content.ts
export interface WeeklyContent {
  week: number;              // 4-40
  trimester: 1 | 2 | 3;
  lengthCm: number | null;   // null = สัปดาห์ 4-7
  weightG: number | null;
  measure: 'crown-rump' | 'crown-heel';
  sizeLabel: string;         // "มะม่วง"
  sizeIcon: string;          // ชื่อไฟล์ SVG
  development: string;       // คำบรรยายพัฒนาการ
}
```
